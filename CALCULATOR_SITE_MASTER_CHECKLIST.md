# Calculator Site Master Checklist

Use this checklist for every calculator website. Reuse the process and code standards, but create a different design, voice, content plan and article set for each domain.

## Brief and research

- [ ] Confirm calculator topic, main keyword, domain, country, language and author
- [ ] Define every input, output, formula, unit, limit and error case
- [ ] Check current search intent and competing page types
- [ ] Identify reliable sources for facts that can change
- [ ] Separate helpful calculation from legal, medical or financial advice

## Make the site original

- [ ] Choose a new design idea, layout model and calculator flow
- [ ] Use a different font pair, colour palette, spacing, icons, borders and result style
- [ ] Create a different topic cluster and article order
- [ ] Write every article from a blank page for the new audience
- [ ] Use new examples, numbers, names, tables and FAQs
- [ ] Run a cross-site similarity check before launch
- [ ] Rewrite repeated sentences or strongly matching outlines

## Calculator quality

- [ ] Check the formula independently
- [ ] Test normal, empty, wrong, reversed and boundary inputs
- [ ] Check rounding, units, dates, leap years and time zones where relevant
- [ ] Write clear error messages that explain the fix
- [ ] Keep results easy to read without depending on colour
- [ ] Verify every privacy claim about local or server-side processing

## Homepage and content

- [ ] Put the exact main keyword in the H1
- [ ] Keep the working calculator easy to reach
- [ ] Add a useful pillar guide below the tool
- [ ] Explain how to use it, how the answer works, examples, mistakes and limits
- [ ] Use the main keyword naturally without stuffing
- [ ] Link to the strongest supporting guides
- [ ] Add author, methodology, privacy and contact pages

## Blog writing style

- [ ] Give each article one clear question to answer
- [ ] Use everyday language for the target reader
- [ ] Keep sentences short and paragraphs focused on one idea
- [ ] Replace difficult words or explain them immediately
- [ ] Include a useful original example
- [ ] Remove filler, unsupported claims and fake experience
- [ ] Write unique titles, descriptions, introductions and conclusions
- [ ] Omit publication dates by default for this portfolio pattern
- [ ] Keep example dates when needed to explain the calculator
- [ ] For India, explain DD/MM/YYYY, completed age, running age and cut-off dates when relevant

## Internal linking

- [ ] Every article links naturally to the calculator homepage
- [ ] Homepage links to important cluster articles
- [ ] Each article links to two to four useful related articles
- [ ] Use varied and accurate anchor text
- [ ] Include breadcrumbs and an all-guides page
- [ ] Confirm there are no orphan pages or broken links

## SEO and trust

- [ ] Give every page a unique title, description, H1 and canonical URL
- [ ] Add accurate Open Graph data and a social image
- [ ] Use structured data only when it matches visible content
- [ ] Generate sitemap and robots files
- [ ] Confirm language, country and production-domain signals
- [ ] Add a truthful author profile and calculation method
- [ ] Make privacy text match real analytics and data handling
- [ ] Add a working public contact method
- [ ] Remove old domains, brands, TODOs and placeholders
- [ ] Never promise a number-one Google ranking

## UI and accessibility

- [ ] Approve a fresh design concept before a major build
- [ ] Test desktop, tablet and mobile
- [ ] Test light and dark themes when included
- [ ] Remove horizontal overflow, clipping and weak contrast
- [ ] Check labels, headings, focus states and keyboard use
- [ ] Test the main calculator flow in a real browser
- [ ] Check the browser console for errors and warnings

## GitHub and Vercel

- [ ] Run production build, type checks, calculation tests and link scans
- [ ] Review files before the first commit
- [ ] Exclude secrets, `.env*`, `.vercel`, caches and temporary QA files
- [ ] Push the reviewed source to the correct GitHub repository
- [ ] Import the repository into Vercel and verify the Astro settings
- [ ] Test the Vercel preview before promoting it
- [ ] Connect the custom domain and preferred hostname
- [ ] Confirm HTTPS, canonical URLs, robots and sitemap in production
- [ ] Add Google Search Console and submit `/sitemap-index.xml`
- [ ] Add analytics only after the privacy page is accurate

## After launch

- [ ] Inspect the homepage and key articles in Search Console
- [ ] Watch queries, impressions, clicks and indexing
- [ ] Improve existing useful pages before creating many new pages
- [ ] Update facts only when the information truly changes
- [ ] Add a new article only when it answers a new reader question
